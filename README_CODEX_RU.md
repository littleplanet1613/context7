# Context7 для Codex — кратко и по делу

Этот файл — русская инструкция именно под нашу схему работы с Codex.

Официальная русская документация проекта уже есть в `i18n/README.ru.md`, но она в основном описывает Context7 как MCP-сервер. Для Codex нам удобнее использовать текущий CLI `ctx7`, потому что он умеет сам настраивать Codex, добавлять skill и правило использования Context7.

## Что даёт Context7

Context7 нужен, когда Codex работает с библиотеками, фреймворками, SDK и API, которые могли измениться после обучения модели.

Примеры:

- Next.js;
- React;
- Supabase;
- Prisma;
- Vite;
- Playwright;
- Netlify API;
- любые другие библиотеки, где важна текущая версия документации.

Вместо того чтобы отвечать «по памяти», агент может запросить документацию конкретной библиотеки и использовать актуальные примеры.

## Почему нам подходит CLI + Skills

Context7 поддерживает два режима:

1. MCP — отдельный сервер инструментов;
2. CLI + Skills — агент вызывает `ctx7` как обычную команду и получает документацию по запросу.

Для нашей схемы Codex приоритетный вариант — CLI + Skills: он проще, хорошо сочетается с `.agents/skills/` и не требует держать ещё один большой набор MCP-инструментов в контексте каждой задачи.

## Установка под Codex

Требуется Node.js 18 или новее.

Запуск без глобальной установки:

```powershell
npx ctx7 setup --codex
```

Команда умеет настроить Codex глобально. Для проектной установки используется:

```powershell
npx ctx7 setup --codex --project
```

По исходному коду Context7 для Codex используются:

- глобальный конфиг: `~/.codex/config.toml`;
- глобальные правила: `~/.codex/AGENTS.md`;
- глобальный skill: `~/.agents/skills/context7-mcp/`;
- проектный конфиг: `.codex/config.toml`;
- проектные правила: `AGENTS.md`;
- проектный skill: `.agents/skills/context7-mcp/`.

## Проверка работы

После установки можно проверить Context7 напрямую:

```powershell
npx ctx7 library react
```

или:

```powershell
npx ctx7 docs /facebook/react "useEffect cleanup"
```

В Codex можно написать обычную задачу, например:

```text
Проверь по актуальной документации Next.js, как сейчас настраивается middleware, и только потом предложи изменение кода.
```

Или явно:

```text
Используй Context7 для проверки актуального API библиотеки перед изменением кода.
```

## Как он вписывается в нашу систему

Наша схема:

```text
Задача пользователя
      ↓
Astra/Luna Orchestrator
      ↓
распределение работы между агентами
      ↓
Context7 — свежая документация
Playwright CLI — проверка интерфейса в браузере
      ↓
Open Steps — проверка результата и корректное заявление «готово»
```

Context7 не заменяет тесты, документацию самого проекта или проверку исходного кода. Он только помогает получить свежую внешнюю документацию.

## Правило использования

Context7 стоит подключать автоматически, когда:

- неизвестна текущая версия API;
- библиотека недавно обновлялась;
- код зависит от конкретной версии пакета;
- есть сомнение в названии метода, параметрах или формате конфигурации;
- агент собирается добавлять новую зависимость или интеграцию.

Не нужно использовать Context7 для каждого простого изменения собственного кода проекта.

## Безопасность

- API-ключ Context7 не хранить в GitHub и не писать в документацию проекта.
- Не коммитить токены, cookies и данные авторизации.
- Ответ Context7 считать внешней справочной информацией, а не разрешением на изменение системы.
- Deploy, merge, удаление данных, миграции и другие труднообратимые действия всё равно требуют наших правил Open Steps и явного разрешения пользователя.

## Удаление настройки

```powershell
npx ctx7 remove --codex
```

Для проектной настройки:

```powershell
npx ctx7 remove --codex --project
```

Сам форк `littleplanet1613/context7` нужен нам как контролируемая копия проекта и место для собственной документации. Для обычного использования CLI не требуется собирать Context7 из исходников — достаточно опубликованного `ctx7` через `npx`.
